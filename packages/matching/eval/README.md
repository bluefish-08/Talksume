# 匹配离线评测（V3 的预演）

```bash
pnpm --filter @talksume/matching run eval          # 汇总表
node eval/run.ts --top                              # 额外打印每个画像的前 5 名
```

## 数据

- `dataset.ts`：5 个合成学生画像（后端本科、算法硕士、产品运营本科、视觉设计实习、数据分析实习），字段按 `Profile` 填写，覆盖不同学历、求职类型和城市限制。
- 评测池 `POOL`：从通过 `SEED_JOBS_PATH` 指定的岗位文件（jobs-ingest 抓取）中挑出的 30 条岗位，覆盖后端、算法、数据、产品、运营、设计、测试、游戏客户端等方向，含实习/校招/社招和多个城市。
- 每个画像对这 30 条逐条标注，未列出的一律为 0。标注人先看岗位名、城市、类型和 JD 要求，再看画像，**没有参考打分系统的输出**；每条标注的理由写在 `labels` 里。

## 标注标准

| 相关度 | 含义                                                                                       |
| ------ | ------------------------------------------------------------------------------------------ |
| 2      | 岗位方向与画像意向和经历一致，技能要求大部分覆盖，类型/城市/学历都可投                     |
| 1      | 相邻方向（如后端投数据开发、视觉设计投交互设计），技能可迁移但职能不同，类型/城市/学历可投 |
| 0      | 职能无关，或类型、城市、学历不满足（这类岗位会被硬性过滤，不进入排序）                     |

## 指标

- 排序只在通过硬性过滤的池内岗位上进行，IDF 用完整 200 条种子库计算。
- P@5：前 5 名中相关度 ≥ 1 的占比；严格 P@5 只算相关度 = 2。
- nDCG@10：增益取 2^rel − 1，理想排序为池内全部标注。
- BM25 基线：同样在通过硬性过滤的岗位上，只用画像文本与 JD 的 BM25 排序，用来衡量五维规则相对纯关键词的增益。

## 局限

- 画像和标注都是人工构造，岗位池只有 30 条且方向差异明显，数字偏乐观；正式的 V3 仍需 10 个真实画像、对前 10 个推荐逐条人工标注。
- 池内「相关」岗位只有 4–8 条，P@5 的上限受此约束；严格 P@5 更能反映同类岗位内部的排序质量。
- 没有评测向量召回与 LLM 报告，二者接入后需要另行对比。

## 分数校准

`src/calibration.test.ts` 用「美团 Go 后端实习、意向后端、上海/杭州」画像对种子岗位断言分数区间与排序：对口且技能命中 85–97，对口但技能部分覆盖 70–90，相邻方向 50–80，仅专业沾边（策划/算法/测试/运营）低于推荐线 30。

计分：技能、意向岗位、经历三项加权得相关度，专业与城市只做最多 15% 的折扣；技能覆盖率取 0.6 次方；85 分以上压缩；JD 要求多年经验而画像不足时整体 ×0.6/0.8；规则分低于 30 的岗位不写入推荐。

## 语义重排（Qwen3-Reranker）

规则打分之后，对前 K=100 个岗位调用 `/rerank`，综合分 =（1 − w）× 规则分 + w × 校准语义分 × 100，再乘反馈系数。

- query：`这个岗位适合以下求职者吗？` + 意向、技能、经历、项目、专业，≤200 字；文档：标题｜公司 + JD 职责前段 + 任职要求，≤300 字。服务端单条输入上限 512 token，超了直接 HTTP 500。问句前缀、保留任职要求都在标注池上实测过：对口岗位概率明显上升，无关岗位仍接近 0。
- 校准：模型输出是相关概率，对口岗位常在 0.05–0.5。按数量级映射：0.001 及以下为 0，0.01≈0.33，0.1≈0.67，1 为 1。单调变换，不改变 rerank 自身的排序，只让混合后的分数刻度与规则分一致。
- 耗时：服务端逐条串行，约 55–70ms/文档，并发请求不会更快；100 条 6.5–7.2s，45 条约 3s。规则打分本身约 0.6s。

`semantic-labeled.ts`（种子池 30 条，无需数据库）：规则 nDCG@10 0.959，w=0.3 时 0.961，w=0.7 时 0.980；池子太小、规则已接近上限，只能说明不伤排序。
